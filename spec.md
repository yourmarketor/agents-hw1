# Спецификация трекера

## Требование: автономная поставка

Результат MUST работать без CDN, внешних библиотек и API-ключей.
Вариант A MUST состоять из tracker-v2.html со встроенными CSS и JavaScript.
Вариант B MUST состоять из index.html, styles.css, app.mjs, domain.mjs
и tests/acceptance.test.mjs.

## Требование: данные и стартовый пример

Каждая задача MUST содержать id, title, hours и done.
Стартовый пример MUST содержать:
- «Чтение»: hours = 2, done = true.
- «Практика»: hours = 4, done = false.
- «Повторение»: hours = 2, done = false.

### Сценарий: стартовый пример
- WHEN загружен стартовый пример,
- THEN всего 8 ч, выполнено 2 ч, прогресс 25%.

## Требование: изменение данных

Добавление, удаление и переключение done MUST изменять данные задач,
а список и показатели MUST отражать актуальные данные.

### Сценарий: добавление
- WHEN отправлена форма с допустимыми названием и часами,
- THEN новая задача добавлена с уникальным id и done = false.

### Сценарий: удаление
- WHEN пользователь удаляет задачу,
- THEN эта задача удалена из данных, список и показатели обновлены.

### Сценарий: выполнение «Практики»
- WHEN в стартовом примере «Практика» отмечена готовой,
- THEN выполнено 6 из 8 ч, прогресс 75%.

### Сценарий: обратное переключение
- WHEN готовая задача переключена в активную,
- THEN done становится false, показатели пересчитаны.

## Требование: проверка формы

Название после trim MUST быть непустым.
Часы MUST быть числом от 0,5 до 24 включительно с шагом 0,5.
Пустое значение часов MUST NOT трактоваться как ноль.
При ошибке задача MUST NOT добавляться.
Ошибка MUST быть видна рядом с соответствующим полем.
Введённые данные формы MUST сохраняться при ошибке.

### Сценарий: пустое название
- WHEN введено пустое название или только пробелы,
- THEN задача не добавлена, рядом с названием видна ошибка,
  введённые данные формы сохранены.

### Сценарий: пустые или отрицательные часы
- WHEN часы пустые или отрицательные,
- THEN задача не добавлена, рядом с часами видна ошибка,
  введённые данные формы сохранены.

### Сценарий: другие недопустимые часы
- WHEN часы не являются числом, меньше 0,5, больше 24
  или не кратны 0,5,
- THEN задача не добавлена, рядом с часами видна ошибка,
  введённые данные формы сохранены.

### Сценарий: границы диапазона
- WHEN название допустимо, а часы равны 0,5 или 24,
- THEN задача добавлена.

## Требование: общие показатели

Прогресс MUST вычисляться как округление
100 × сумма часов готовых задач / сумма часов всех задач.
При отсутствии задач итоговые часы и прогресс MUST быть нулевыми.
Показатели MUST NOT содержать NaN или Infinity.

### Сценарий: удаление всех задач
- WHEN все задачи удалены,
- THEN всего 0 ч, выполнено 0 ч, прогресс 0%.

## Требование: фильтрация

Интерфейс MUST предоставлять фильтры «все / активные / готовые».
Фильтр MUST влиять только на видимый список.
Общие часы, выполненные часы и прогресс MUST считаться по всем задачам.

### Сценарий: активные задачи
- WHEN в стартовом примере включён фильтр «активные»,
- THEN видны «Практика» и «Повторение», всего остаётся 8 ч,
  выполнено 2 ч, прогресс остаётся 25%.

### Сценарий: готовые задачи
- WHEN в стартовом примере включён фильтр «готовые»,
- THEN видно только «Чтение», показатели остаются 8 ч, 2 ч и 25%.

### Сценарий: все задачи
- WHEN включён фильтр «все»,
- THEN видны все задачи независимо от done.

## Требование: интерфейс

Интерфейс MUST быть читаемым на ширине 390 px
без горизонтального скролла.
Поля и кнопки MUST иметь понятные подписи.

### Сценарий: узкий экран
- WHEN ширина области просмотра равна 390 px,
- THEN поля, кнопки, список и показатели читаемы и доступны,
  горизонтального скролла нет.

## Необязательное улучшение: localStorage

Если улучшение реализовано, задачи MUST сохраняться в localStorage
и восстанавливаться при следующем запуске.
При недоступности хранилища интерфейс MUST показывать понятное
сообщение и MUST продолжать работу в памяти.

### Сценарий: сохранение
- WHEN задачи изменены и приложение запущено повторно
  при доступном хранилище,
- THEN восстановлены сохранённые задачи.

### Сценарий: недоступное хранилище
- WHEN чтение или запись localStorage недоступны,
- THEN показано понятное сообщение, добавление, удаление
  и переключение выполнения продолжают работать в памяти.
