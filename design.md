# Проектирование

## Модель данных

| Поле | Тип | Правило |
|---|---|---|
| id | строка | Уникальный идентификатор задачи |
| title | строка | Непустое название после trim |
| hours | число | От 0,5 до 24 включительно, кратно 0,5 |
| done | логическое значение | Признак выполнения |

Стартовые данные:

| id | title | hours | done |
|---|---|---:|---|
| reading | Чтение | 2 | true |
| practice | Практика | 4 | false |
| review | Повторение | 2 | false |

## Состояние интерфейса

- Массив задач — источник данных для списка и расчётов.
- Текущий фильтр: «все», «активные» или «готовые».
- Введённые значения формы.
- Ошибки отдельно для названия и часов.

Часы до проверки хранятся как введённый текст, чтобы отличать
пустое значение от числа и сохранять ввод при ошибке.

## Проверка формы

1. Проверить непустое название после trim.
2. Проверить часы на пустое значение до преобразования в число.
3. Проверить, что часы — конечное число в диапазоне 0,5–24.
4. Проверить кратность 0,5.
5. При ошибке оставить массив задач и ввод без изменений,
   показать ошибки рядом с соответствующими полями.
6. При успехе добавить задачу с обработанным названием,
   числовыми часами, уникальным id и done = false.

## Расчёты

- Общие часы = сумма hours всех задач.
- Выполненные часы = сумма hours задач с done = true.
- Если общие часы равны 0, прогресс = 0%.
- Иначе прогресс = округление до ближайшего целого
  (100 × выполненные часы / общие часы).

Контрольные значения:

| Состояние | Общие часы | Выполненные часы | Прогресс |
|---|---:|---:|---:|
| Стартовый пример | 8 | 2 | 25% |
| «Практика» отмечена готовой | 8 | 6 | 75% |
| Все задачи удалены | 0 | 0 | 0% |

## Фильтрация и изменения

«Все» показывает весь массив, «активные» — задачи с done = false,
«готовые» — задачи с done = true.

Фильтр не изменяет массив задач и не участвует в расчётах.
Удаление и переключение done выполняются по id.
После изменения данных обновляются видимый список и общие показатели.

## Размещение по файлам

Вариант A:
- tracker-v2.html: разметка, стили, данные, расчёты и обработчики.

Вариант B:
- index.html: разметка интерфейса.
- styles.css: оформление и адаптация к ширине 390 px.
- app.mjs: состояние интерфейса, события и отображение.
- domain.mjs: проверка данных, операции над задачами,
  фильтрация и расчёты.
- tests/acceptance.test.mjs: автоматические проверки доменной логики
  средствами Node.js без внешних библиотек.

Визуальная приёмка и взаимодействие с формой проверяются в браузере
отдельно от доменных тестов.

## Необязательное сохранение

При реализации localStorage:
- При отсутствии сохранённых данных загрузить стартовый пример.
- Сохранённый пустой массив считать корректным состоянием,
  не заменять его стартовым примером.
- Сохранять задачи после успешных изменений.
- Ошибки доступа к хранилищу перехватывать, показывать понятное
  сообщение и продолжать работу с текущими данными в памяти.
